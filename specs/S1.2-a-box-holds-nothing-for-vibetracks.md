# S1.2 A box holds nothing for Vibe Tracks, and tree changes never write a box

## Requirement

> I think a change is that the tracks are basically completley self contained and indpdent... / they really no nothign about each other.
>
> None of the agents should have a vibetracks.toml / each agent is compeltely indpdent and self contained.

Zach, Daily Note - Nov 24 2026, # Vibe tracks. Quoted exactly. [OBJECTIVES.md §4](../OBJECTIVES.md#4-the-spec) lists every item; this note
explains it and never overrides it.

## What it means

No box carries a Vibe Tracks file (no `vibetracks.toml`, no `vibe-parent:` key, nothing). No box names another
box. Moving, pinning, renaming, archiving or deleting a track in the sidebar changes Vibe Tracks' own file only: the
box's working tree and its git history are untouched. The only writes into a box are the box's own content a person
asked for, in the box's own format (a feedback note into its `feedback/`, §3.3).

## Why

Zach first suggested a `vibetracks.toml` per box, then reversed it the same evening. Boxes stay reusable on any
machine, with or without Vibe Tracks, and a box's git history stays about its work.

## How it is checked

`S1.2 *`: after a scripted run of every sidebar verb (drag, pin, rename, archive, move to section, delete) over the
fixture boxes, each box's `git status --porcelain` is empty, its HEAD is unchanged, and no file under any box
matches `*vibetrack*` or `*vibe-tracks*`. A fixture box with a `vibetracks.toml` dropped in by the test changes
nothing on the page (the file is ignored).
