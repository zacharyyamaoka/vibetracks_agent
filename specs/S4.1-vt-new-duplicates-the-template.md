# S4.1 `vt new` makes a new box by duplicating the black-box template

## Requirement

> right now to make a new track is basically to it would duplciate the blackbox agent repo. / so I think with the vibetracks cli there should be like vibetracks new or something that does that..

Zach, Daily Note - Nov 24 2026, # Vibe tracks. Quoted exactly. [OBJECTIVES.md](../OBJECTIVES.md) lists every item; this note
explains it and never overrides it.

## What it means

`vt new "<title>" [--parent <track>] [--dir <folder>] [--publish]` copies the blackbox_agent starter box into a
new folder, fills its title, makes it a git repo with one first commit, and lists it in Vibe Tracks' tree under the
parent. `--from <track>` duplicates an existing box instead (the ··· menu's Fork). Works offline.

## Why

A track is now a box, so a new track is a new box. One command, so an agent can do it as easily as Zach
(Principle #1; "no need to ask my permission of course to add new vibe tracks", Oct 26).

## How it is checked

`S4.1 *`: in a temp home with no network: exit 0; the folder is a git repo with one commit; its README's first
heading is the title; its file set contains the starter box's file set at the frozen blackbox_agent ref; the track is
in the tree under the parent; `--from` copies the source box's files minus its history.
