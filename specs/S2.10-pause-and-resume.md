# S2.10 Pause a track; a paused track looks paused and stays paused until resumed

I think in the 3 button menu You can give like a pause/resume, archive, delete, So if I want a track to not improve for some reason I can pause it. otherwise this agent should be making usre that the track is actively continuing towards completeion.

Zach, 2026-11-25, typed in the Agent Activity Agent's chat and relayed verbatim to this box
([feedback/2026-11-25-pause-a-track.md](../feedback/2026-11-25-pause-a-track.md)). Quoted exactly. It became

## What it means

- A track's ··· menu (and its right-click menu, S2.4) has **Pause** `Z` right before Archive (S2.3); on a paused
  track it reads **Resume** `Z`.
- Pausing is Vibe Tracks' own state, kept in its own tree file beside pinned and archived (vibetracks PEP 0024:
  `<vt home>/tree.json`): it never writes the box (S1.2).
- A paused row looks paused: a pause glyph in the status-dot slot and a muted title. Claude has no paused row; this is
  the closest honest look. Resume puts back the row's state colour and the menu's **Pause**.
- It survives a reload and a `vt serve` restart.
- **Who paused it is recorded.** The tree file's entry for the track keeps an append-only `status` list; the latest
  record wins and an empty list means active. One record is `{at, status: paused | active, by[, why]}`, where `by` is
  vibetracks' own stamp: `person` always; `agent`, `model`, `sid` (and `account`) only when an agent's session ran the
  verb; `via` is `page` or `cli`. A pause from the page is a person record; `vt pause` run inside an agent's session
  is an agent record (vt stamps it; the caller can't).
- Parity: `vt pause <track> [--why "<text>"]` and `vt resume <track> [--why "<text>"]` (the track named by its box
  folder's basename, like `vt add --parent`) do the same as the menu. `--why` is stored verbatim on that record as
  `why`; without it the record has no `why` key.

## Why

So a track Zach does not want pushed can be held still, and every other open track is expected to keep moving
toward done. The Agent Activity Agent reads the records: a track is open unless done, paused or archived **by a
person**, so an agent-set pause keeps it open unless its `why` cites a person-signed answer whose option is pause
(PEP 0002, "The record"). Vibe Tracks only stores `why`; it never reads it to decide anything.
