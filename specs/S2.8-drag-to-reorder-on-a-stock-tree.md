# S2.8 Drag to reorder and to move under another track, on a stock tree component

## Requirement

> and it supports that easily we can just like drag to reorder the tracks in the side bar.
>
> (So I think we should deinftily use like a stock tree here etc to get thoose nice folder/drag and drop reordering interactions)

Zach, Daily Note - Nov 24 2026, # Vibe tracks. Quoted exactly. [OBJECTIVES.md §4](../OBJECTIVES.md#4-the-spec) lists every item; this note
explains it and never overrides it.

## What it means

In the Parent grouping, dragging a row between two rows reorders it; dropping it onto a row makes it that
row's child; dragging it out to the left makes it top-level. A drop line or a highlighted target shows where it will
land before the drop. A track can never be dropped into its own subtree. The same moves work from the keyboard. The
tree model and drag behaviour come from a stock component, not hand-rolled code; the rows keep Claude's look (S2.2).

## Why

Zach's ask, and [[feedback_availability_before_originality]]. The prior-art sweep (Nov 24) picks Headless Tree's
`@headless-tree/core` (MIT, no dependencies, ordered drag with reparenting, keyboard; renders nothing, so the Claude
rows stay) with Atlassian Pragmatic drag and drop as the fallback; react-arborist and @atlaskit/tree need React and
Wunderbaum draws its own rows.

## How it is checked

`S2.8 *`: real pointer drags (Playwright mouse down/move/up) for each of the four moves, the drop indicator's box
measured mid-drag, the result read back after a restart; a drop into its own child is refused; the keyboard path does
one reorder. Which library is used is checked by the page loading a known stock tree package, named in
`ruler/reference/stock-trees.json`.
