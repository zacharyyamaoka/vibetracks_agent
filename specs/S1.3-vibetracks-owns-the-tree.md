# S1.3 Vibe Tracks owns the tree: parent, child, order, pins and sections

## Requirement

> Its vibe tracks that basically like defines that parent child relationship.

Zach, Daily Note - Nov 24 2026, # Vibe tracks. Quoted exactly. [OBJECTIVES.md](../OBJECTIVES.md) lists every item; this note
explains it and never overrides it.

## What it means

Which track sits under which, in what order, what is pinned, which named sections exist and what is
archived are all kept in Vibe Tracks' own file(s), outside every box. A person can read and edit that file by hand
(Principle #1, parity), and a hand edit shows in the sidebar within a tick. The same box can be listed once.

## Why

The parent/child relationship is a fact about how Zach organises his work, not about any box. Keeping it in one
place is what lets boxes stay independent (S1.2) and lets a drag reorganise everything (S2.8).

## How it is checked

`S1.3 *`: the tree set by drags survives a `vt serve` restart; the file that changed lives outside every box;
editing that file by hand (moving one entry under another) moves the row in the sidebar within 5 s with no reload.
