# S4.3 Local-only by default; publishing to GitHub is an option that needs `gh` signed in

## Requirement

> vibetracks should require that you are loged into github btw. beacuse then it will kinda like make a new github repo for you...
>
> wella ctually that should be an option wether you want to publish it yet or not we should support local only tracks.

Zach, Daily Note - Nov 24 2026, # Vibe tracks. Quoted exactly. [OBJECTIVES.md §4](../OBJECTIVES.md#4-the-spec) lists every item; this note
explains it and never overrides it.

## What it means

Without `--publish`, nothing leaves the machine and no GitHub sign-in is needed. With `--publish`, `vt new`
checks `gh auth status` before making anything; signed out, it stops, names `gh auth login`, and creates nothing.
Signed in, it creates a **private** repo (public only with `--public`) and pushes the first commit. A local track can be
published later from its ··· menu (Open in › shows GitHub once it is).

## Why

His correction in the same breath: GitHub is an option, local-only tracks are supported. Private by default:
a first public push is a step nothing undoes.

## How it is checked

`S4.3 *`: with a fake `gh` on PATH that records its arguments: no `--publish` → never called; signed out → exit
non-zero, message names `gh auth login`, no folder made; signed in → `repo create <name> --private --source <dir>
--push` called once.
